- **Persistence** (`db/`): SQLAlchemy 2.0 models (Trial 1–* Document 1–* Section),

  a data-access layer (`repository.py`) with **idempotent upserts** (created/updated/

- **Verify:** schema/DAL/idempotency tests on in-memory SQLite; MarkItDown tests with a

fallback for scanned PDFs (flagged, not yet implemented); background-job persistence

## Milestone 4 — Unified summarization engine + hosted providers ✅ (done, verified)

Status: implemented and verified (`ruff` clean, `pytest` 50 passing). SDK calls are
covered by **fully mocked** tests — no SDKs installed, no keys, no network, no cost.

- **Unified interface** (from M2): `SummarizerBackend` + `SummaryResult` carrying text,
  model, generation config, input/output tokens, latency, estimated cost, warnings,
  run id, and provenance. Local backends (Lead, DistilBERT, HF generative) already use it.
- **Hosted providers** (`providers/`): Anthropic, OpenAI, Gemini as drop-in backends.
  SDK APIs verified via Context7 (anthropic messages, openai chat completions,
  google-genai generate_content). Lazy SDK imports behind the optional `[providers]` extra.
- **Key safety:** keys from env or passed explicitly (user-supplied), never hardcoded,
  never logged, masked in output; `validate()` checks config without a network call.
- **Error handling:** normalized taxonomy (ProviderConfigError / Auth / RateLimit /
  Response) mapped from SDK errors by status code / class name.
- **Cost:** pricing registry + `estimate_cost`; ships **empty** (no fabricated prices) →
  "cost unknown" until populated from official pricing pages.
- **Extensibility:** add a provider = one subclass + one registry entry.
- **CLI:** `pls providers` (masked key status) and `--backend <provider>[:<model>]`.
- **Verify:** mocked success paths for all three providers; key masking; missing-key
  config error (no network); error classification; graceful per-example failure in the
  harness when a key is absent. ✔

## Milestone 5 — Benchmarking + experiment tracking + fine-tuning ✅ (done, verified)

Status: implemented and verified (`ruff` clean, `pytest` 60 passing, `pls benchmark`
runs multi-backend end-to-end and persists an experiment; migration chain up-to-head
verified on a fresh DB).

- **Benchmark runner** (`evaluation/benchmark.py`): evaluates several backends on the
  *same* examples; captures reproducibility context (software versions, seed, generation
  config, an order-independent fingerprint of the exact examples); emits machine-readable
  JSON + a Markdown comparison table. Reuses the failure-tolerant harness.
- **Experiment persistence** (DB): `Experiment` + `ExperimentResult` tables (Alembic
  migration autogenerated), `repository.save_experiment` / `list_experiments`.
- **Fine-tuning** (`training/`): pure, tested data-prep (prompt pairs, **leakage check**,
  stats) + a GPU-gated seq2seq trainer (`finetune.py`) with early stopping, optional
  **LoRA** via the `[peft]` extra, checkpoint + metadata. Defaults to an encoder-decoder
  (abstractive) rather than the thesis's extractive DistilBERT.
- **CLI:** `pls benchmark` (`--to-db`), `pls experiments`, `pls train` (`--lora`).
- **Verify:** benchmark/fingerprint/table/experiment-persistence tested on SQLite + Lead
  backends; data-prep + leakage tested; trainer's missing-`[ml]` guard tested. The actual
  train loop is **not** run in CI (no GPU/downloads) — documented, run deliberately. ✔

## Milestone 6 — RAG research assistant ✅ (done, verified)

Status: implemented and verified (`ruff` clean, `pytest` 73 passing; `pls index/ask/rag-eval`
run end-to-end on the synthetic sample, CPU-only, no ML deps).

- **Chunking** (`rag/chunk.py`): within-section, sentence-boundary windows with overlap,
  preserving `trial_name`, `section`, and char offsets for precise citations.
- **Embeddings** (`rag/embeddings.py`): dependency-free `HashingEmbedder` default (real
  signed-hashing bag-of-words, L2-normalized) so RAG runs anywhere; `SentenceTransformer`
  behind the optional `[rag]` extra for stronger retrieval.
- **Store/retrieval** (`rag/store.py`): in-memory cosine top-k with trial scoping;
  chunks + vectors persist in a `chunks` table (Alembic migration). pgvector is the
  documented scale path.
- **Assistant** (`rag/assistant.py`): reuses any `SummarizerBackend`; returns citations
  (trial/section/offsets) and an explicit **insufficient-evidence** response below a
  tunable threshold. Retrieved text is labeled reference data with an injection guard;
  backends are text-only (no tools), so retrieved content can't trigger actions.
- **Retrieval evaluation** (`rag/eval.py`): recall@k / precision@k / MRR, with relevance
  derived from the dataset's own question→section mapping — measured separately from
  answer quality.
- **CLI:** `pls index`, `pls ask`, `pls rag-eval`.
- **Verify:** embedder determinism/similarity, chunking + offsets, store top-k + filter,
  assistant citations + insufficient paths + injection guard, and the retrieval metrics —
  all tested CPU-only. ✔

Note: the default hashing embedder is deliberately weak (no semantics); retrieval quality
on real data improves markedly with the `[rag]` sentence-transformer embedder. Metrics are
reported honestly, never inflated.

- Exact thesis metric numbers are not in the repo; they will be **re-measured**, labeled as such, and never copied from the published thesis as if reproduced here.
